# GuidingHand 1.0 — real-phone acceptance

Release version: **1.0**. Internal Android upgrade code14 is retained to update the existing installation without uninstalling. The initial Meta debug adapter adds an optional planning path; historical user observations below apply to the earlier local build until repeated.

Device: Xiaomi 2602DPT53G, Android API36, with Zalo and Instagram installed. Installation and Accessibility connection were verified through ADB. Current JVM checks passed with **106 tests**; they do not replace the physical checks below.

## Confirmed user observations

- The hand bubble opens the compact assistant.
- The card follows bubble dragging; Find an app → Help menu returns to the root prompt.
- The mini-chat is compact and draggable.
- Guide hides while locked and returns after unlocking.
- Optional online speech hears the request. An earlier report of successful offline Vietnamese recognition was corrected by the user: offline Vietnamese was unavailable.
- Launcher swipes run and guidance continues. Downward navigation opened the Xiaomi system panel during development and was removed.
- The final translucent moving cue is easy to see and swipes correctly.
- After English → Vietnamese → English interface switching, the guide and speech dialog use the correct language in both modes.
- With the initial Meta debug adapter installed, the user followed the Meta opt-in/Calculator test instructions and reported a ring on the correct control. Additional settled gateway requests corroborated API activity; no control-level trace or latency measurement was collected.
- With the goal planner and pointing hand installed, the user confirmed that the new app picker opened Calculator and showed Try an example. They then reported the indicated taps reached 168 and the guide asked whether the task was finished. Additional settled API requests corroborated activity; other goals and edge/lifecycle variants remain unverified.

These observations apply to this Xiaomi and the reported interactions only.

## Acceptance checklist

1. **Language:** choose Vietnamese; language labels become Tiếng Anh/Tiếng Việt. Check Home, preferences, bubble, help menu, app finding/swipe recovery, recipient confirmation, speech-language support/download/error/online consent and safety messages. Choose Tiếng Anh and repeat in English. Switch with a card expanded and while speech or recording is active: old cards, utterances and results must not return. Reopen after process recreation to check persistence; unsaved family fields must survive a locale change. Recognition language remains separate. Actual app/provider/contact names and user input retain their spelling. Common controls from an English app are offered in Vietnamese and vice versa; unknown controls use localized numbered choices and highlighted-control instructions. Underlying apps and system Settings keep their own language. Missing TTS models show a localized setup message without speaking another language.
2. **Bubble and retention:** open Instagram and tap Guide. The current app must stay in front with a small overlay. Drag in both directions and near edges; release docks without accidentally opening a card. Tap still opens the card. Minimize/restore the card and use underlying controls. Hide/Stop/disable/recreation must leave no stale ring or invisible touch-blocking window. A separate Xiaomi accessibility shortcut is a system feature.
3. **Voice:** microphone capture starts only after an explicit tap and permission. Test denied permission, missing language, unclear speech, cancel and retry. Choose instead must remain available. Test installed/downloadable/pending/unsupported/unknown offline language states. Model download requires a tap and never starts recording automatically. Online recognition discloses and binds the selected system provider, asks per utterance, stops on cancel/lock and never silently replaces offline mode. Language metadata and JVM fixtures do not establish acoustic accuracy.
4. **Installed-app finding:** choose Find an app and select an installed app. Point to a real unique launcher icon or accessible Search field; the user performs taps and typing. If no target is visible, demonstrate left; Other way cycles right, up, then left. Manual swipes refresh guidance. Swipe for me performs exactly one requested stroke only on safe, complete, unlocked Home with gesture capability, no focused editor, TalkBack touch exploration or magnification. Interactive overlays are absent during the stroke. Re-read actual targets afterward; gesture completion alone never means app success. Search query text must not be mistaken for an app icon. Handle alternate pages/folders without inventing targets. Completion requires the selected app's actual package transition.
5. **Recipient:** say a name or choose a saved contact, then confirm it. Ambiguity must not select another person. The user searches and types inside Zalo/Instagram when needed. Continue in an overlay on the selected app without returning to GuidingHand Home. End messaging guidance at the correctly focused message field; never compose or send for the user.
6. **Card and cue:** inspect light/dark/photo backgrounds and large text. Cards remain close to the bubble, inside bounds and clear of the highlighted target. Check edges, corners, changing heights and Help menu on every substep. The thin swipe track and circle must pass touches through. The circle demonstrates motion; it does not track a manual finger. Swipe for me illustrates its one stroke. Minimize/hide/help/lock/destruction cancel motion; restoring a card refreshes foreground ownership before restoring the cue. Disabled system animations use a static circle. Repeat/Stop remain reachable; waiting must not advance or falsely complete a task.
7. **Wrong taps and stale results:** a wrong tap replans from the new tree without erasing verified history or claiming success. Duplicate taps and unchanged frames cannot advance. Unknown/incomplete/ambiguous screens stop safely. Late backend and gesture callbacks must not restore guidance after Stop, Help menu, Hide, a language change or lock.
8. **Video and photo tasks:** use a consenting test contact and harmless photo. Require actual call-state evidence. Photo picker closure alone is insufficient; require newly exposed outgoing-photo and delivery evidence. Otherwise stop as unconfirmed. Never call or send automatically.
9. **Font, Wi-Fi and scanning:** single-tap accessible font choices may be guided; slider-only controls stop. A selected Wi-Fi network must newly become connected. Password entry stops guidance. Scanning requires accessible viewport/result evidence; do not invent results from a camera preview.
10. **Sensitive screens:** password/payment/OTP content stops rings, speech and planning before processing. Call family opens the saved number in the dialer without starting the call. Guidance cannot resume while the sensitive screen remains. Do not export private, password, payment or lock/passcode screenshots.
11. **Lock and lifecycle:** lock with only the bubble visible, an expanded card, active cue and microphone capture. Waking without unlocking must restore nothing; speech and microphone stop. Unlock restores only the bubble, respects Hide and never automatically resumes a task. Repeat after service recreation. The confirmed basic lock/unlock result does not establish all these variants.
12. **General current-screen guidance:** in another app, choose a uniquely labeled control or speak its supported translated label. Highlight the actual node bounds. Duplicate/unlabeled controls must not be invented. A changed screen asks what next without claiming an arbitrary goal is complete. The optional Spark adapter selects grounded choices only; it is not universal goal understanding.
13. **Meta debug mode — initial Calculator ring reported; remaining acceptance pending:** use a test account and synthetic photo only. Pair through USB, then explicitly consent in Preferences. Trigger supported guidance on a non-sensitive test screen and check the ring and localized instruction. Disable Meta, disconnect USB, change language, Stop and lock during a pending request: late responses must not revive a ring. Service recreation must return to local mode. Review only usage counters; never export private screens, provider keys or pairing tokens. The reported single-control check does not establish these remaining scenarios.
